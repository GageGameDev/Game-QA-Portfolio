📋 Bug Reporting Methodology

My bug reports aim to document the following information:

1. Bug Title: Concise description of the issue.
2. Game and Platform: Game title and hardware.
3. Game Version: Version or update information when available.
4. Severity: Estimated impact on gameplay or functionality.
5. Description: Detailed explanation of the observed problem.
6. Steps to Reproduce: Instructions for attempting to reproduce the issue.
7. Expected Result: How the feature should behave.
8. Actual Result: What occurred during testing.
9. Reproduction Frequency: How consistently the issue occurs.
10. Evidence: Screenshots or supporting documentation when available.
11. Workaround: Temporary solution, if discovered.
12. Status: Current testing or verification status.

I aim to distinguish between confirmed observations, possible causes, and issues requiring further testing.
